# 網羅すべきテストの観点: エンティティとドメインサービス

`references/testing.md` の観点に加えて書く。適用の考え方（契約があるときに適用する、独立した制約を1つずつ違反させる）と、どのモデルにも共通の観点はそちらにある。書き方は `references/test-style.md` にある。

---

## エンティティ

### 生成

- [ ] 自動で決まる項目（識別子、作成時刻、初期状態、空のコレクション）が期待どおり埋まる。期待値は Then でダミー生成ヘルパーを使って組み、`toStrictEqual` で比べる（検査対象の関数の出力からは作らない）
- [ ] 結果が凍結されている
- [ ] 入れ子のオブジェクトと配列も凍結されている（`.readonly()` の凍結は1階層だけなので、別の契約）
- [ ] 配列の要素も凍結されている。**配列の凍結とは別のテストにする**（配列の `.readonly()` と要素のスキーマの `.readonly()` は別々に外れうる。要素が1つ以上ある結果で確かめる。実物は `example/domain/entity/Task.test.ts` の `Task.addComment`）
- [ ] create の第1引数の各項目の制約が効く（代表の1ケース。細かい境界値は項目を持つモデルで確かめる）
- [ ] 余剰キーを実行時に拒否する
- [ ] 生成器が不正な値を返すと、入力のエラー（`InvalidCreationParamError`）ではなく `InvalidClockValueError` / 識別子の型ごとの class（`InvalidGeneratedCommentIdError` など） になる
- [ ] 生成器そのものが投げた例外は、包まれずにそのまま伝わる（Then で `toBe` によって同じ例外かを見る）

### 型

`references/test-style-type-tests.md` の書き方で、`Xxx.test-d.ts` に書き、Vitest の型検査モードで確かめる。

- [ ] `references/testing.md` の「型のテストを置くモデル」の表の3箇所にある項目ごとに、そこに書いた4種類のうち当てはまるものをすべて書いた（代表の1項目にしない）

### 複数状態

- [ ] 遷移後の値全体が期待どおり。期待値は遷移先の状態のダミーで組む
- [ ] **その状態に存在しない項目のキーが無い**（`"startedAt" in result` が `false`）
- [ ] 遷移元の状態を限定する。許さない状態ごとに、名前付きのエラーになる
- [ ] 遷移の前提条件（タイムスタンプの前後など）を満たさないと、名前付きのエラーになる
- [ ] 前提条件の境界（同じタイムスタンプを許すかどうか）
- [ ] 遷移しても、引数で受け取った値が変わらない
- [ ] `reconstruct` が、状態の不変条件（作成時刻より前の着手時刻など）を破る保存値を拒否する

### 値オブジェクトに切り出していない項目の書き換え

- [ ] 書き換えた結果の値全体が期待どおり
- [ ] 項目の制約に違反する値を、名前付きのエラーで拒否する（制約ごとに1ケース）。エラーは対象の識別子と、違反した条件を指す `issues` を持つ
- [ ] 書き換えても、引数で受け取った値が変わらない

```ts
describe("Task.complete", () => {
	test("正常系: 完了した Task は startedAt のキーを持たない", () => {
		// Given: 着手中の Task と、着手時刻より後の完了時刻があるとき
		const task = createDummyInProgressTask({ startedAt: 2_000 });
		const at = createDummyTimestamp(3_000);

		// When: その Task を完了させると
		const result = Task.complete(task, { at });

		// Then: startedAt のキーを持たない完了した Task になる
		expect("startedAt" in result).toBe(false);
	});
});
```

### 操作だけが持つ引数の条件

- [ ] 条件に違反する引数（使うポイント数が0・負・小数など）を、その規則だけを表す名前のエラーで拒否する。状態との関係の違反（残高不足）とは別の種別であることを確かめる（`references/model-code.md` の「業務操作で Zod を使わない」）
- [ ] 違反の種類ごとに1ケース。条件の境界（1は受け入れる）も確かめる

### 任意項目

- [ ] **渡さなければキーごと存在しない**
- [ ] 渡せば値が入る

### 導出値

- [ ] 生成時に計算される
- [ ] 依存元を変える操作で再計算される
- [ ] **再計算を忘れた値を完成値スキーマが拒否する**（`reconstruct` に食い違った値を渡す）
- [ ] 導出値の上限（合計が上限を超えるなど）は `create` と業務操作で確かめ、`reconstruct` には写さない（`references/test-style.md` の「境界値をどこで確かめるか」）

### 横断検証が例外を投げない

**このグループは必須。** 完成値スキーマの `safeParse` が「不正な値には例外を投げず失敗を返す」という契約を守れているかを直接確かめる。
`create` / `reconstruct` / 業務操作は、この契約を前提に失敗を名前の付いたエラーに包む（規則6）。
型が合わない入力は `reconstruct` に渡せない（引数が `XxxSchemaInput`）ので、テストでは完成値スキーマを直接呼ぶ。
不正な値の種類ごとに1テスト。

- [ ] 要素間の制約違反（識別子の重複など）で検証を通らない
- [ ] 要素の制約違反（負の値など）で検証を通らない
- [ ] 型が違う入力（配列であるべき項目が文字列）で検証を通らない
- [ ] 入れ子が壊れた入力（要素が `null`）で検証を通らない

```ts
describe("TaskSchema", () => {
	test("正常系: comments が配列でなければ検証を通らない", () => {
		// Given: comments を文字列に差し替えた Task の値があるとき
		const task = createDummyBacklogTask();
		const value = { ...task, comments: "配列ではない" };

		// When: その値を TaskSchema で検証すると
		const result = TaskSchema.safeParse(value).success;

		// Then: 検証を通らない
		expect(result).toBe(false);
	});
});
```

### 副作用

- [ ] **入力の検証に失敗したとき、生成器（`idGenerator` / `clock`）を呼ばない**
- [ ] **入力だけで決まる導出に失敗したとき、生成器を呼ばない**（個々の入力は有効でも、組み合わせから導出できない場合を入れる）
- [ ] 生成器の戻り値を使う導出の失敗は、この保証の対象にしない

戻り値を見るだけでは確かめられない。Given で `vi.fn` を作って依存に渡し、呼ばれていないことを見る。
失敗の種別はほかのテストに任せ、このテストの Then は呼び出しの有無だけにする。

### 等価性

- [ ] 識別子が同じなら、ほかの項目が違っても等しい
- [ ] 識別子が違えば、ほかの項目が同じでも等しくない

### 集約の中の子エンティティを扱う操作

- [ ] 追加した結果の値（子の識別子と作成時刻が、操作に渡した依存から決まっている）
- [ ] 子の `create` の入力が不正なとき、子の `create` のエラーが操作からそのまま伝わる
- [ ] 生成器が不正な値を返すとき、子の `create` の `InvalidClockValueError` / 識別子の型ごとの class（`InvalidGeneratedCommentIdError` など） が操作からそのまま伝わる
- [ ] 重複を名前付きのエラーで拒否する
- [ ] 並び順の制約（投稿順など）を破る追加を、名前付きのエラーで拒否する
- [ ] **上限に達した状態で追加すると、専用のエラーを投げる**（`FatalUnreachableError` にならない）

## ドメインサービス: I/O の無い判定

参照実装に実物は無い。作ることになったときに、業務操作の観点に加えて確かめること。

- [ ] 判定を満たすとき、期待する結果を返す（期待値はダミーで組む）
- [ ] 判定の境界で、同じ値を許すかどうかが仕様どおり
- [ ] 判定に違反したとき、何が起きたかを表す名前のエラーを投げ、対象の識別子と比べた値を持つ
- [ ] 渡された集約の組み合わせが前提を満たさないとき、黙って捨てずに名前の付いたエラーで拒否する
- [ ] 渡した集約を変更しない

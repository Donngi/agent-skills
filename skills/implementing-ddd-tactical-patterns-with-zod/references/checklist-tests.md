# 完了の確認: テスト

`references/checklist.md` の項目と合わせて確かめる。確認するのは、対象に該当し、今回採用した規約で有効な項目だけである（適用の考え方は `SKILL.md` の「完了の確認」）。

- [ ] エラー class のコンストラクタに生の値と別種の識別子を渡せないことを、そのエラーを定義したファイルの `Xxx.test-d.ts` で確かめている
- [ ] 型のテストで別種の値を渡すのは識別子どうしだけで、識別子以外のブランド付きの値どうし（時刻と金額など）の取り違えのテストを書いていない（`references/testing.md`「型のテストを置くモデル」）
- [ ] テストの書き方で、既存の規則・流儀と `references/test-style.md` の既定がぶつかる項目だけを利用者に確認している（利用者の指示には確認せず従い、確認できない場面では既存に従って、そう判断した項目を回答に書いている）
- [ ] `references/testing.md` と、書いたモデルの種類に当たる `references/testing-*.md` の観点をすべて書いた
- [ ] 〔check.mjs〕テストが `references/test-style.md` の書き方に沿っている（Given / When / Then、1テスト1契約、`test.for`、`toThrow(具象の class)`、`toStrictEqual`）
- [ ] 〔check.mjs〕すべての `// Given:` `// When:` `// Then:` に説明があり、そのセクションのコードと食い違っていない（テストを直したら説明も直している）
- [ ] `reconstruct` のテストが、成功1つと、種別と `operation` を確かめる代表の失敗1つ（キーを持つ値では余剰キーの拒否）と、`create` では渡せない値の検証だけで、`create` で確かめた境界値（導出値の上限を含む）を写していない（`references/test-style.md`「境界値をどこで確かめるか」）
- [ ] 凍結のテストが、結果・入れ子の配列・配列の要素で分かれている（1つのテストにまとめていない。`references/test-style.md`「1つのテストで確かめること」）
- [ ] export した定数に `describe` を立てていない（境界はその定数を使う操作の `describe` の中にある）
- [ ] 拒否を確かめる値が、狙った制約のほかを満たしている。空文字・前後の空白の行と、書き出し（`https://` など）の検査も持つ値で先頭に違反文字を置いた行と、DTO で本体を壊した行（保存キーを組み直したか。組み直せない型の違反なら issue の `code` と `path` を確かめたか）と、別の値オブジェクトを組み込んだ識別子の行（部品は部品の制約を満たすか）を1行ずつ見た（`references/testing.md` の冒頭の、独立した制約の扱い）
- [ ] テスト名と説明でモデル名を訳していない。モデルそのものを指す文は英名で、項目として述べる文だけを日本語にしている。Given で英名で書いたモデルを「その」で指し直す文も英名にしている（`references/comments.md`「語の選び方」）
- [ ] 説明に、ヘルパーの既定値と比べた言い方（「既定の依存」「既定と違う〜」）が無い（`references/test-style.md`「説明の書き方」）
- [ ] Vitest の設定が無かったなら、ヘルパーの除外と型検査を入れた `vitest.config.ts` を作り、そのことを回答に書いた（既存の設定を変えたなら、変える前に利用者に確認した）
- [ ] リポジトリ実装と、保存先に問い合わせるドメインサービスの実装に、クライアントをモックに差し替えたテストがある（本物のクライアントを使っていない。I/O の無いドメインサービスはモックなしで確かめる）
- [ ] 値オブジェクトとエンティティのすべてに `Xxx.helper.test.ts` があり、ダミーを `reconstruct` で作っている（DTO はテストに書き下ろしている）
- [ ] 〔check.mjs〕`references/testing.md`「型のテストを置くモデル」の3か所（create の第1引数・業務操作のパラメータ・エラーのコンストラクタ引数）に当たる引数を持つファイル（エラー class を定義したファイルを含む）に `Xxx.test-d.ts` があり、型検査を有効にした `vitest run` の結果に型のテストが出て、すべて成功している（単一プリミティブの値オブジェクトと列挙には置いていない）
- [ ] `vitest run --coverage` の Branches と、`if` の外にある判定の読み合わせで C1 を確かめ、到達しない分岐とハック無しではテストできない分岐（区分は `references/testing.md`「到達しない分岐」）を除いて網羅した（除外した分岐を理由とともに回答に書いた。除外コメントで隠していない）

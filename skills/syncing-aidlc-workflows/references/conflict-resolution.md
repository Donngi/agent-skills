# 衝突の解消手順

`aidlc_merge.sh` は自動マージできない箇所を**衝突**として残す。衝突は `kind` で種類が分かれる。

## kind 別の対処

### `merge`（テキストの3-way衝突）— 最も一般的

ローカルと上流が**同じ箇所**を別々に変更した場合。install 先のファイルに衝突マーカーが書き込まれる。

```
<<<<<<< ローカル変更 (あなた)
（あなたが編集した内容）
||||||| 前回取込 (base)
（前回取り込んだ上流の内容）
=======
（新しい上流の内容）
>>>>>>> 上流新版
```

> `||||||| 前回取込 (base)` セクションは、git の `merge.conflictStyle` が diff3/zdiff3 の場合に出る
> （base が見えるので解決しやすい）。出ない設定でも `<<<<<<<` / `=======` / `>>>>>>>` は必ず出る。

**解消**: ファイルを開き、3者の意図を踏まえて正しい1つの内容に書き換え、マーカー行
（`<<<<<<<`, `|||||||`, `=======`, `>>>>>>>`）をすべて削除する。ローカルの意図と上流の新仕様の
両方を活かすのが基本。判断に迷う箇所はユーザーに確認する。

### `delete-modified`（上流が削除 × ローカルで改変）

上流はこのファイルを消したが、ローカルで内容を変えていた。マーカーは付かず、**ローカル版が install に
残る**。ユーザーに「上流は不要と判断したファイルです。あなたの変更を残しますか／削除しますか」を確認:

- 残す → そのまま（以後このファイルは追跡対象外のローカル独自ファイルになる）
- 削除する → `rm` する

### `delete-update`（ローカルで削除 × 上流が更新）

ローカルで消したファイルを上流が更新した。既定では**復活させない**（install に無いまま）。
ユーザーが新版を欲しければ、`base/` または `incoming/` 相当の新版から手動でコピーする。

### `add-add`（同名ファイルがローカルと上流で別内容）

追跡外だった同名ファイルがローカルにあり、上流が同じパスに新規追加した。テキストなら空 base での
マージ結果（マーカー付き）が書き込まれるので `merge` と同様にマーカーを解消する。なお `add-add` は
`kind` が `merge` 以外として記録されるため、マーカーを消したうえで finalize は `--accept` も必要になる
（マーカー検証と二段で確認する形）。

### `binary`（テキストでない）

3-way マージできないため**ローカルを保持**する。新版が必要なら手動で置き換える。
（現状の aidlc dist は md/json/js/hook の全テキストなので通常は発生しない。）

## finalize での検証

`aidlc_finalize.sh` は以下を確認してから確定する:

1. install 先に `<<<<<<<` / `>>>>>>>` マーカーが**一切残っていない**こと（残れば停止）。
2. `merge` 以外の衝突（delete-modified 等）が記録されている場合は、対処を確認のうえ `--accept` を要求。

マーカーを消し忘れるとそのまま install に残り壊れた状態になるため、finalize のこのチェックが
最後の安全網になる。base は finalize まで不変なので、停止しても何度でもやり直せる。

## やり直したいとき

merge を丸ごと取り消すには:

```bash
bash "${SKILL}/lib/aidlc_merge.sh" --project-root "${PROJECT}" --abort
```

merge 直前の installPath（`backup-<ts>/` に退避済み）へ復元し、`pendingUpdate` と `incoming/` を破棄する。
